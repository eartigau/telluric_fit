Telluric Correction Pipeline

A six-step pipeline for correcting telluric absorption in NIRPS and SPIRou infrared échelle spectra — from raw data sync through fully corrected science output.

The pipeline combines TAPAS-based atmospheric modelling with empirical per-pixel residual corrections to achieve high-fidelity telluric removal for precision radial-velocity work and spectral characterisation.

Pipeline at a glance

bash sync_NIRPS
Step 1 — Sync · rsync calibrations, hot-stars and science data from the remote server
→ calib_NIRPS/  ·  hotstars_NIRPS/  ·  scidata_NIRPS/
python slinky_tools.py
Step 2 — Slinky · correct FP cavity drift in wavelength solutions
→ calib_NIRPS_patched/  ·  slinky_NIRPS_output/
python smart_fit.py
Step 3 — Hot Star Fit · fit H₂O, CH₄, CO₂, O₂ exponents from hot-star spectra
→ tellu_fit_NIRPS/trans_*.fits
python compil_stats.py
Step 4 — Compile Stats · aggregate statistics, fit seasonal/secular models
→ params_fit_tellu_NIRPS.csv  ·  main_absorber_NIRPS.fits
python residuals.py
Step 5 — Residuals · build per-pixel empirical correction maps from hot-star residuals
→ residuals_NIRPS/residuals_order_XX_*.fits
python predict_abso.py
Step 6 — Telluric Correction · apply model + residual correction to all science targets
→ tellupatched_NIRPS/{OBJ}_{batch}/
One-command run: python run_pipeline.py executes all six steps in order. Read the run_pipeline.py section for flags.

⚡ Quick Start

Prerequisites

  • Conda environment p3.12 (or equivalent) with astropy, scipy, numpy, tqdm, numexpr, yaml, matplotlib
  • Access to the remote data server (rali or equivalent) via SSH
  • telluric_config.yaml configured for your machine (see Machines)

First run (full pipeline)

# Activate environment
conda activate p3.12
# Run all 6 steps
python run_pipeline.py

Typical partial runs

# Skip sync (data already present locally)
python run_pipeline.py --skip-sync

# Re-run only the telluric correction on one object
python run_pipeline.py --only-telluric --object PROXIMA

# Run only slinky (wavelength solution update)
python run_pipeline.py --only-slinky

# Process a single object end-to-end (skip sync + slinky)
python run_pipeline.py --skip-sync --skip-slinky --object TOI270

# Use SPIRou instead of NIRPS
python run_pipeline.py --instrument SPIROU

Reset for a clean re-reduction

# Dry run — shows what will be deleted, nothing is removed
python reset.py --dry-run

# Actually delete all pipeline byproducts
python reset.py

# Skip confirmation prompt (e.g., for scripting)
python reset.py --force
Warning: reset.py permanently deletes all computed products (fitted transmissions, residual maps, corrected spectra, etc.). Input data in scidata_*/, hotstars_*/, calib_*/ and templates_*/ are never touched.

⚙️ Configuration — telluric_config.yaml

All pipeline behaviour is controlled by a single YAML file. The most commonly edited sections are described below.

Top-level instrument settings

KeyDefaultDescription
instrumentNIRPSNIRPS or SPIROU — determines all derived directory names and calibration files.
template_stylesmartmodel uses a synthetic stellar model; self uses a median of the target's own spectra; smart auto-selects self if a template already exists, otherwise model.

Target lists

KeyDescription
hot_starsList of hot-star names used by smart_fit.py and compil_stats.py. Add one name per line. Names must match filenames in hotstars_NIRPS/.
science_targetsList of science targets processed by predict_abso.py (and patched by slinky). Each name must match a sub-directory in scidata_NIRPS/.
data_recipientsMaps collaborator usernames to the targets they should receive. Used by datashare.py to copy corrected spectra and set ACL permissions. A target can appear under multiple recipients; targets without a recipient are not shared.

Batch settings

batch:
  name: 'v28Apr2026'     # Batch identifier — appears in output folder names
  generate_plots: true
  plot_orders: [30, 60]    # Order range for diagnostic PDFs
Tip: Change batch.name to version your outputs. Each batch produces its own tellupatched_NIRPS/{OBJ}_{batch}/ sub-directory, so multiple batches can coexist.

Processing parameters

KeyDefaultDescription
processing.randomize_filestrueShuffle file order; helps with parallel execution.
processing.lowpass_filter_size101Low-pass filter window (pixels) for continuum normalisation.
processing.hotstar_medfilt_width150 km/sRunning-median width (km/s) for hot-star continuum.
processing.dv_amp200 km/sVelocity search range for RV estimation.
processing.sky_rejection_threshold1.0Reject pixels where sky/sp_corr exceeds this value.

Quality control thresholds

KeyDefaultDescription

quality_control.o2_airm_max1.08Maximum valid O₂ airmass.

Per-molecule depth thresholds

Moleculedepth_maxdepth_saturatedreject_saturated
H₂O0.60.50.8
CH₄0.50.20.8
CO₂0.50.20.8

Pixels below depth_max transmission are down-weighted. Pixels below depth_saturated contaminate neighbours out to reject_saturated via the sigmoid-weight transition (weighting.transition_sigma).

All directories live under project_path (machine-specific, see Machines).

project_path/

  residuals_NIRPS/ # Per-order residual maps (slope/intercept/rms) — GENERATED

    PROXIMA_v28Apr2026/ # One sub-dir per object × batch
  tmp_NIRPS/ # Precomputed absorption grid cache (.pkl) — GENERATED
  slinky_NIRPS_output/ # Science files with corrected wave extension — GENERATED
  slinky_NIRPS_plots/ # Slinky diagnostic plots — GENERATED

2Slinky — Wavelength Solution Refinement

Command

python slinky_tools.py
# or via pipeline:
python run_pipeline.py --only-slinky

What it does

FP-based wavelength calibrations drift due to Fabry-Perot cavity length variations (the "slinky" effect). This step measures and removes that drift by correlating FP and HC (hollow-cathode) line lists.

  1. Match FP / HC line-list files by MJD from calib_NIRPS/
  2. Compute cavity values for each HC line using FP peak numbers
  3. Fit zero-point and slope of cavity drift per epoch (iterative σ-clipping)
  4. Patch wavelength solutions with GP-smoothed per-line residuals (kernel length = wslinky)
  5. Replace wave extensions in all science and hot-star files

Configuration (slinky: section)

ParameterDefaultDescription
doplotfalseShow interactive diagnostic plots during processing
wave_leverage1600 nmLeverage point for the linear cavity fit
wslinky0.1 nmAutocorrelation length of the GP smoothing kernel

Required inputs (in calib_NIRPS/)

Glob patternContent
*wave_fplines_A.fitsFP line-position tables (one per epoch)
*wave_hclines_A.fitsHC line-position tables (one per epoch)
*_wavesol_ref_A.fitsReference wavelength solution
*waveref_hclines*A.fitsHC reference line list

Outputs

DirectoryContents
calib_NIRPS_patched/Patched wavelength solution FITS files — used automatically by downstream steps
slinky_NIRPS_output/Science files with corrected WaveA extension
slinky_NIRPS_plots/Cavity median, zero-point/slope trends, HC/FP residual plots
calib_NIRPS/*_slinky.fitsPer-HC-frame augmented line-list (deleted by reset.py)
Steps 3–6 automatically prefer wave solutions from calib_NIRPS_patched/ when available; if slinky has not been run they fall back to calib_NIRPS/.

3Hot Star Telluric Fitting

Command

python smart_fit.py

What it does

Processes all hot-star spectra listed in hot_stars: to determine the atmospheric transmission function. Hot stars have featureless IR spectra, making them ideal telluric calibrators.

  1. Load reference wavelength grid, blaze function, and sky PCA components
  2. For each hot-star spectrum: resample → normalise → subtract sky (OH airglow via PCA) → divide by blaze
  3. Optimise absorption exponents one molecule at a time, starting from airmass as an initial guess
  4. Write corrected transmission and updated FITS header

Molecules fitted

MoleculeHeader keyPhysical meaning
H₂OEXPO_H2OColumn water vapour; highly variable
CH₄EXPO_CH4Methane; seasonal variation
CO₂EXPO_CO2CO₂; secular increase + annual cycle
O₂EXPO_O2Oxygen A-band; constant mixing ratio

Output

tellu_fit_NIRPS/trans_*.fits — one file per hot-star observation, containing the fitted transmission spectrum and all derived header keywords.

Example console output

4Compile Statistics

Command

python compil_stats.py

What it does

Aggregates telluric parameters from all trans_*.fits headers to build statistical models used by predict_abso.py.

  1. Build big table — reads all FITS headers from tellu_fit_NIRPS/; cached in big_table.csv for fast re-runs
  2. QC filtering — discards exposures outside o2_airm_min / o2_airm_max (twilight fluorescence)
  3. Fit temporal models for CO₂ (secular + annual cycle), CH₄ (seasonal), O₂ (airmass-only)
  4. Identify dominant absorber per pixel → main_absorber_NIRPS.fits
  5. Write parameter CSV → params_fit_tellu_NIRPS.csv

Physical models

MoleculeModelReason
CO₂Secular trend + annual sinusoid~2 ppm/yr increase; Northern-Hemisphere biosphere cycle
CH₄Seasonal sinusoidBiosphere + anthropogenic sources
O₂Airmass scaling onlyConstant 20.95% mixing ratio
H₂OFitted per-observationToo variable for a statistical model

Outputs

FileDescription
params_fit_tellu_NIRPS.csvFitted atmospheric model parameters consumed by predict_abso.py
main_absorber_NIRPS.fitsInteger map (0=H₂O, 1=CO₂, 2=CH₄, 3=O₂) of the dominant absorber per pixel
tellu_fit_NIRPS/big_table.csvCached master table of all hot-star headers (regenerated when stale)

5Residual Modelling

Command

python residuals.py

What it does

Builds per-pixel empirical correction maps from the ensemble of hot-star residuals. These capture systematic errors not modelled by TAPAS (line position shifts, depth biases, instrumental artefacts).

  1. Load all trans_*.fits from tellu_fit_NIRPS/
  2. BERV-align residuals to a common wavelength grid
  3. Per-pixel linear fit: slope vs EXPO_H2O (for water pixels) or vs AIRMASS (for O₂/CO₂/CH₄)
  4. Compute RMS after model subtraction
  5. Build a smoothed RMS envelope (median filter + Savitzky-Golay)

Quality filters applied

  • Only hot stars with EXPO_H2O < 7.0
  • Require > 50% valid pixels per order for the fit
  • Pixels with RMS > rms_excess_factor × envelope are masked (set to NaN) in subsequent steps

Outputs (residuals_NIRPS/)

File patternDescription
residuals_order_XX_slope.fitsSlope of the linear correction (per pixel)
residuals_order_XX_intercept.fitsIntercept of the linear correction
residuals_order_XX_rms.fitsRMS after correction (quality metric)
residuals_order_XX_rms_envelope.fitsSmoothed RMS envelope (masking threshold)
This step is optional but recommended. If residuals_NIRPS/ is absent, predict_abso.py still runs but skips the per-pixel empirical correction, leaving systematic residuals in the output.

6Telluric Correction — predict_abso.py

Commands

# All science_targets from config (default)
python predict_abso.py

# Single object
python predict_abso.py --object PROXIMA

# Via pipeline driver
python run_pipeline.py --only-telluric
python run_pipeline.py --only-telluric --object TOI270

What it does

Applies the full telluric correction to science targets using the models from steps 3–5.

  1. Load per-exposure wavelength grid, spectrum, airmass, pressure
  2. Load or generate stellar template (model / self / smart)
  3. Estimate radial velocity via cross-correlation (search range ±dv_amp km/s)
  4. Build TAPAS atmospheric transmission at observation conditions using parameters from params_fit_tellu_NIRPS.csv
  5. Subtract sky emission via PCA
  6. Apply per-pixel residual correction from residuals_NIRPS/
  7. Mask saturated telluric pixels (NaN) based on depth thresholds
  8. Write *tellupatched_t.fits output file

Template styles

StyleBehaviourWhen to use
modelUse a synthetic stellar model from the libraryFirst run; few observed epochs
selfBuild template from median of the target's own corrected spectraMany epochs available; iterative refinement
smartUse self if templates_NIRPS/Template_s1dv_{obj}_*.fits exists, else modelRecommended default

Output

Corrected spectra are written to tellupatched_NIRPS/{OBJ}_{batchname}/. File names follow the pattern:

*tellupatched_t.fits   # telluric-corrected 2D e2dsff spectrum

Per-object progress tracking

The script skips files for which the output tellupatched_t.fits already exists in the batch directory, enabling safe interruption and restart.

📤 Data Sharing — datashare.py

Copies telluric-corrected spectra to collaborators' scratch folders and sets ACL read permissions. Recipients, their targets, names, and email addresses are defined in data_recipients: in telluric_config.yaml.

Usage

python datashare.py                      # copy all recipients + set ACL + print emails
python datashare.py --dry-run            # preview without copying
python datashare.py --email-only         # only print email draft summaries
python datashare.py --send-email         # interactive menu to send emails via Gmail
python datashare.py --user fbel          # process a single recipient
python datashare.py --instrument SPIROU  # override instrument
python datashare.py --no-prompt          # skip prompts for missing name/email (batch mode)

How it works

  1. Reads data_recipients from telluric_config.yaml
  2. Prompts for any missing name or email address and saves them back to the yaml
  3. For each recipient, copies tellupatched_{instrument}/{TARGET}/ → /scratch/eartigau/datashare/{user}/{TARGET}/
  4. Sets setfacl ACL permissions so the user can read their folder
  5. Prints ready-to-send email drafts with a polite greeting using the recipient's real name
  6. With --send-email: shows a numbered list of recipients — type the numbers of those to email and press Enter

Sending data to a single person

# Copy files + interactive email menu for Flavie only:
python datashare.py --send-email --user fbel

# Files already copied — just send the email:
python datashare.py --email-only --send-email --user fbel

▶ run_pipeline.py — Full Pipeline Driver

The top-level driver that chains all six steps. Reads defaults from telluric_config.yaml.

All flags

python run_pipeline.py [FLAGS]

## Step control
  --skip-sync          Skip rsync step
  --skip-slinky        Skip slinky wavelength correction
  --skip-hotstar       Skip hot-star fit (smart_fit.py)
  --skip-compilstats   Skip compil_stats (params_fit_tellu + main_absorber)
  --skip-residuals     Skip residual modelling

  --object NAME               Process a single object
  --batch  NAME               Override batch name

## Template
  --template model|self|smart  Override template style

## Misc
  --recompute        Force recomputation of the absorption grid cache

💧 Atmospheric Molecules

The pipeline models four atmospheric absorbers using TAPAS-computed opacity grids.

MoleculeSymbolSpectral regionVariability
Water vapourH₂OAll NIR ordersHigh — fitted per-observation
Carbon dioxideCO₂1.6 µm, 2.0 µmSecular + annual cycle (~2 ppm/yr)
MethaneCH₄1.7 µm, 2.3 µmSeasonal + anthropogenic trend
OxygenO₂0.76 µm (A-band)Fixed mixing ratio (20.95%)

Absorption model

Each molecule's transmission is modelled as:

T(λ) = T_TAPAS(λ)^exponent

where exponent ≈ airmass × (column_density / reference_density). The exponent is optimised independently for each molecule and each exposure during Step 3.

O₂ quality control

Twilight observations contaminate O₂ measurements via OH Meinel band fluorescence. Exposures with O2_AIRM outside [o2_airm_min, o2_airm_max] are excluded from the statistical fit in Step 4.

🔧 Troubleshooting

Console output colour codes

ColourMeaning
GreenProgress messages — what the pipeline is doing
BlueNumerical values and derived parameters
CyanHot-star banners with progress [n/N]
OrangeWarnings — issues requiring attention
RedErrors

Common problems

Missing calibration files

Re-run bash sync_NIRPS. Check SSH connectivity to the remote server.

Exponent optimisation does not converge

  • Verify hot-star spectrum quality (check SNR in header)
  • Confirm sky subtraction worked (check sky PCA components file exists)
  • Review airmass values — extreme airmasses (> 2.5) can cause problems

FileNotFoundError: templates_NIRPS/Template_s1dv_…

The template for this object is missing. Either:

  • Run with --template model to use a synthetic model instead, or
  • Re-run the sync to download the template from the server

Science correction produces NaN-filled spectra

  • Reduce rms_excess_factor slightly (e.g. 2.5 → 2.0) — but stay ≥ 1.5
  • Check that residuals_NIRPS/ exists and has all order files
  • Verify template RV is within the dv_amp search range

Output spectra exist but are not updated after config change

predict_abso.py skips files that already have an output. Delete the relevant sub-directory in tellupatched_NIRPS/, or use a new batch name, then re-run.

Pipeline very slow on a single core

On multi-core machines, increase n_cores in the machine configuration or run individual objects in parallel:

# Run two objects in parallel in separate terminals
python predict_abso.py --object PROXIMA &
python predict_abso.py --object TOI270 &
